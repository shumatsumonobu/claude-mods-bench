# ドキュメントの書き方

このファイルに足すもの ── ドキュメントの構成と文体  
実装の仕様は mods.md、進め方は workflow.md

**文体と用語の決まりは、このリポジトリの全ドキュメントに適用する**  
README だけでなく、`CLAUDE.md` と `.claude/rules/` 自身も従う

## 最重要の方針

**導入は `/plugin` で済ませる**

- mod は 2026-10 から公式に `/plugin` で入れられる
- 完成した mod はリポジトリの `mods/<name>/` に置き、読者は `/plugin marketplace add` と `/plugin install` で入れる
- 各ファイルの全文を README に貼る必要は無い（読者はリポジトリのファイルをそのまま読める）

## root README は着地ページ

リポジトリの顔として、開いた瞬間に、何が入っていて何がうれしいかが伝わること  
形は作者の別リポジトリ（loop-engineering-playbook）の README にそろえる

構成の順番

1. 太字の1文（何が入っていて、どう入れられるか）と、確かめた Claude Code のバージョン
2. 収録している mod ── 1本ごとに、名前（リンク）・何をするか・困りごと・できること・スクショ1枚
3. 導入 ── 番号付きの手順（marketplace を登録、mod を入れる、起動し直す）
4. mod が使う機能を確かめる ── `claude plugin validate` の `calls:`
5. mod とは ── 何ができるか、手を入れられる場所の図（数は書かない）
6. shell hook との違い
7. 参照 ── 読む人が次に行く先だけに絞る、作る人向けの資料や、存在を確かめていないリンクは載せない
8. ディレクトリ構成 ── 導入する側に要らないものはその旨を添える、位置は最後（冒頭は何ができるかを見せる場所）
9. Author と License

作る人向けの細かい実測は README に載せず、`.claude/rules/mods.md` に書く  
下の6見出し固定は、per-mod README の決まり

## per-mod README は6見出しで固定

全ての mod で同じ順番  
中身が無い節は落とすが、順番は変えない

````markdown
# <name>

Claude Code の mod（Claude Code の動きや画面を変えられるプラグイン）  
（何をするかを1文）

## 課題

（症状を具体的に、機能の説明ではなく、読者が心当たりのある困りごと）

## 導入

Claude Code 2.1.287 以降が必要（`claude --version` で確認）  
早期公開のときに `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` を設定していたら削除（2.1.287 以降は無視される、[公式の mods の概要のページ](https://code.claude.com/docs/en/plugins/mods/overview)）

1. このリポジトリを marketplace（プラグインの配布元）として登録

   ```
   /plugin marketplace add <owner>/<repo>
   ```

2. <name> を入れる

   ```
   /plugin install <name>@<marketplace>
   ```

3. Claude Code を起動し直す ── 次の起動から有効、初回に作業フォルダの信頼を求められたら承認  
   開いたままのセッションなら、`/reload-plugins` でも読み込める（[公式の mods の概要のページ](https://code.claude.com/docs/en/plugins/mods/overview)）

## 動作

（実際に出た文字列とスクショ、作文しない）

## 設定

（`/config` の行の名前から変える形で書く、`settings.json` の `pluginConfigs` に直接書く形も添える）
（`userConfig` に収まらない設定は、収まらない理由を書く、変えるものが無ければ節ごと落とす）

## 設計上の理由

（shell hook で書いた場合に届かない点）

## 仕様上の注意

（ドキュメントに無い Claude Code 側の挙動、無ければ節ごと落とす）
````

## 導入の節の決まり

- **手順は番号付きにする** ── 1. marketplace を登録、2. mod を入れる、3. 起動し直す、の順に、コマンドは手順ごとに分けてコマンドブロックで書く
- **`author` は作者名にそろえる** ── `plugin.json` と `marketplace.json` の `author` は `週末ものづくり部`（README の Author と LICENSE と同じ）
- **全文を貼る場合だけ、実物とバイト一致させる** ── README に `register.ts` を貼るなら実物と `diff`、実装を直したら貼り直す  
  貼らないほうが基本（読者はリポジトリのファイルを読める）
- **スクリーンショットはリポジトリ直下の `screenshots/` にまとめる** ── README からは相対パス（`../../screenshots/<file>.png`）で参照  
  全部同じ端末幅・同じ拡大率で撮る、画面の右に出るものは端末の横幅が144文字以上ないと写らない

## 文体

全ドキュメントに適用する

- **初めて読む人に分かる言葉で書く** ── 内輪の言い換えや造語を使わない  
  画面の場所は、プロンプトの上の1行・画面の右のように見た目で書く  
  公式ドキュメントにある語（`ui.render` `Pane` など）はそのまま使う
- **主語を省いて、誰の話か分からなくしない** ── 入れた mod、ではなく、ほかの人が作った mod を入れたとき、のように書く
- **mod が画面に出す文字は英語** ── ボタン・見出し・一覧・`/config` の値  
  README など説明文は日本語、公式サンプル（Token Weather など）とそろえる
- **体言止めを使い、句点を使わない** ── 〜を拒否する、で終えず、〜を拒否、で終える
- **1行に1文** ── 文の途中に句点を入れて文をつながない、つなぐなら読点か「──」
- **1文ずつ空行で区切らない** ── GitHub は段落の間を大きく空けるので、並ぶものはリストにまとめる
- **補足が1行ならリストを入れ子にしない** ── 行末にスペース2つで改行し、同じ項目の中で次の行に書く
- **見出しに説明を詰めない** ── 見出しは短く、説明は本文かリストに書く
- **判定記号と絵文字を使わない** ── 語で書く
- **鍵括弧で強調しない**
- **数を予告しない** ── 2点で届かない、のような書き方は、節が増えたときに矛盾する
- **事実と推測を混ぜない** ── 実測したものと、読んだだけのものを分けて書く
- **公式ドキュメントを根拠に挙げるときは、ページ名をリンクにする** ── 公式の mods の概要のページ、と名前だけで書かず、読者がその場で開けるようにする

## 用語

検索から直接そのページに来る読者を想定し、初出で1回だけ補う

| 語 | 補い方 |
|---|---|
| mod | Claude Code の mod（Claude Code の動きや画面を変えられるプラグイン） |
| shell hook | `settings.json` に定義する従来のフック |
| marketplace | プラグインの配布元 |
| `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` | 早期公開のときに mod を有効にしたスイッチ、2.1.287 からは無視される（[公式の mods の概要のページ](https://code.claude.com/docs/en/plugins/mods/overview)）、手元の 2.1.285 では必要だった（実測1回） |

- [ ] 全文を貼った場合、`register.ts` が実物とバイト一致しているか
- [ ] `plugin.json` と `marketplace.json` の `author` が `週末ものづくり部` か
- [ ] 設定例のパターンが実際に当たるか（作文しない、実行して確かめる）
- [ ] 設計上の理由が書けたか

- [ ] 着地ページの構成どおりか（太字の1文 → 収録 mod とスクショ → 導入 → 使う機能を確かめる → mod とは → 違い → 参照 → ディレクトリ構成 → Author と License）

- [ ] 作る人向けの細かい実測を載せていないか（mods.md に書く）

全ドキュメント共通

- [ ] 体言止めで、句点が無いか（行末も文の途中も）
- [ ] 1文ずつ空行で区切っていないか、見出しに説明を詰めていないか
- [ ] 数を予告していないか
- [ ] 判定記号と絵文字が無いか

- [ ] 実測と、読んだだけのものが区別されているか
